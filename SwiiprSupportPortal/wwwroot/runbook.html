Support Runbook & FAQ

How to use the portal and what to do when the platform API misbehaves.

Using the portal

  1. Open Card Export and sign in, or paste a bearer token into the token box (kept for this browser tab only).
  2. Paste card tokens (any length; one per line, Excel paste is fine) or upload a .txt/.csv file.
  3. Click Fetch transactions, watch per-token status, then Download CSV. Use Retry failed for failures.
  4. If a column looks wrong, use Show raw / Copy raw JSON on that token to see the platform response.

Token and JWT tips

  • A bearer token expires (usually within an hour). Use the JWT Decoder to check exp; decoding happens locally.
  • Paste the token without the leading Bearer (it is stripped if present).
  • Never share tokens in tickets or chat. Treat them like passwords.
  • Clean messy lists first with Bulk Token Utilities.

Common API errors

StatusMeaningWhat to do
401Token missing, invalid or expiredSign in again or paste a fresh token, then Retry failed.
403Signed in but not allowed for this card/resourceCheck your role/scope (access_as_user) and that the card belongs to an accessible programme.
404Card token not foundVerify the token for typos or the wrong environment.
429Rate limitedThe portal retries with back-off automatically; lower concurrency or wait a minute, then retry.
5xxPlatform or upstream (Paynetics) problemRetried automatically. If it persists, check platform status and raise with the on-call engineer.

FAQ

Why does the CSV have a RawResponse column? Failed tokens are written as a row with the card token and the raw response so nothing is silently dropped.

Is anything uploaded or stored? No. Utilities run in your browser. Only the checklist ticks are stored (localStorage).
